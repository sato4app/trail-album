# trail-album - 写真入りKMZをExcelに出力

## 1. 概要

ハイキングで撮った写真の KMZ ファイルを読み込み、写真と属性（名称・撮影日時・位置）の一覧の
**Excel ファイル（KMZ と同じ名前の .xlsx）**と、**元の画質の写真ファイル**をまとめて保存する Web アプリです。
画面には「Trail Album」と表示されます。

- 出力したフォルダは、KMZ のままでは中身を見にくい写真データのバックアップとして使います。
- Excel は「目次」、photos フォルダの写真は「元の画質のまま残す本体」という役割分担です。
- 処理はすべてブラウザの中で行い、写真を外部へ送信しません。

主な入力は、箕面ハイキングアプリ（minoh-hiking）の写真の「出力」で作った KMZ です。

## 2. 使い方

1. 「KMZ ファイルを選ぶ」を押すか、KMZ ファイルを画面にドラッグ＆ドロップします。
2. 写真の一覧（撮影日時の順）と、出力フォルダ名（予定）を確かめます。写真を押すと元の写真を大きく表示します。
3. 保存します。
   - **フォルダに保存**（Chrome・Edge）: 保存先のフォルダの中に出力フォルダを作って保存します。
     同じ名前のフォルダがあるときは上書きせず、「名前 (2)」のように番号を付けます。
     保存先は最初に1回選べば覚えておき、次からは選ぶ画面を出さずに保存します（「保存先を変更」で選び直せます）。
     ブラウザを開き直した後の最初の保存では、書き込みを許可するか確かめられます。
     Chrome 122 以降は、そこで「毎回許可」を選ぶと次からは確かめられません。
   - **ZIP でダウンロード**（すべてのブラウザ）: 出力フォルダと同じ構成の ZIP をダウンロードします。
     展開してから Excel ファイルを開いてください（展開せずに開くと、Excel のリンクから写真を開けません）。

「元の KMZ も一緒に保存する」を ON（既定）にすると、読み込んだ KMZ もそのまま保存します。

## 3. 出力

```
20261118_箕面/                       … 出力フォルダ（KML の Document 名。日付で始まらないときは「最も早い撮影日_」を前に付ける）
├─ 20261118_箕面.xlsx                … 写真の一覧（KMZ と同じ名前）
├─ photos/
│  ├─ 001_20261118-1032_箕面大滝.jpg  … 番号_撮影日時(日本時間)_名称（KMZ 内の写真をそのまま保存）
│  └─ ...
└─ 20261118_箕面.kmz                 … 読み込んだ KMZ（選んだときのみ）
```

Excel ファイルの内容:

| シート | 内容 |
|---|---|
| 写真一覧 | No.・サムネイル（長辺 約400px の縮小版）・名称・撮影日時（日本時間の日付型）・緯度・経度・地理院地図/Google マップへのリンク・写真ファイルへのリンク・備考（空欄） |
| 情報 | 元の KMZ のファイル名、KML の Document 名、写真の枚数、出力日時、作成アプリ、注意書き |

- サムネイルは「セルに合わせて移動やサイズ変更をする」配置にしています。撮影日時などで並べ替えたり、
  オートフィルターで絞り込んだりすると、画像も行と一緒に動きます（絞り込んだ行の画像は隠れます）。
- ファイル名・フォルダ名では、Windows で使えない文字（`\ / : * ? " < > |`）と制御文字を除きます。
  Excel のリンクが働くよう、`#` と `%` も除きます。名称部分は40文字までにします。
- 写真のファイル名では、名称部分の空白（全角の空白を含む）を `_` に置き換えます（`箕面 大滝` → `箕面_大滝`）。
  名称に元からある `-` はそのまま残します。
  Excel の「名称」列は元の名称（空白を含む）のままです。

## 4. ファイル構成

```
trail-album/
├─ public/
│  ├─ index.html
│  ├─ style.css
│  └─ js/
│     ├─ app.js            … エントリポイント（画面の制御）
│     ├─ kmz-reader.js     … KMZ の展開・KML の解析
│     ├─ excel-writer.js   … Excel ファイル（.xlsx）の作成
│     ├─ thumbnail.js      … サムネイルの作成
│     ├─ saver.js          … フォルダへの保存・ZIP の作成
│     └─ naming.js         … フォルダ名・ファイル名の作成と使えない文字の除去
├─ .github/workflows/
│  └─ pages.yml            … public を GitHub Pages に公開する
├─ vercel.json             … outputDirectory を public にする
└─ README.md
```

- Vanilla JavaScript + ES6 モジュール。ビルド工程はありません。
- 外部ライブラリは CDN（jsDelivr）からバージョンを固定し、改ざん検知（SRI）付きで読み込みます。
  - JSZip 3.10.1（KMZ の展開・ZIP の作成）
  - ExcelJS 4.4.0（Excel ファイルの作成）
- ページの通信先は Content-Security-Policy（`connect-src 'self'`）でこのサイトの中だけに制限しています。

## 5. 開発・デプロイ

ローカルで確認するときは、`public` フォルダでローカルサーバーを起動します（ES モジュールのため、
index.html を直接開くと動きません。フォルダへの直接保存も https か localhost でのみ使えます）。

```bash
cd public
python -m http.server 8000
# ブラウザで http://localhost:8000 を開く
```

Vercel には、`public` を出力先とする静的サイトとしてデプロイします（ビルドコマンドなし）。

GitHub Pages（https://sato4app.github.io/trail-album/）には、`main` に push するたびに
GitHub Actions（`.github/workflows/pages.yml`）が `public` フォルダを公開します。
リポジトリの Settings → Pages → Source は「GitHub Actions」にしておきます
（「Deploy from a branch」のままだと、ルートに index.html が無いため README.md が表示されます）。
