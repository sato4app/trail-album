# trail-album 開発指示書

## 1. 概要

ハイキングで撮った写真の KMZ ファイルを読み込み、写真と属性（名称・撮影日時・位置）を一覧にした
**Excel ファイル（.xlsx）と元の画質の写真ファイル**をまとめて出力する Web アプリを作る。

出力したフォルダは、KMZ のままでは中身を見にくい写真データの**バックアップ（保管場所）**として使う。
Excel は「目次」、写真は「元の画質のまま残す本体」という役割分担にする。

- アプリ名: `trail-album`（画面表示は「Trail Album」）
- 配置場所: `C:\Users\showa\Documents\地図アプリ\trail-album\`
- デプロイ先: Vercel（静的サイト。Vercel のプロジェクト名も `trail-album`）

## 2. 基本方針

- **ブラウザだけで完結する。** サーバー処理・外部 API への送信は行わない（写真を外部へ送らない）。
- **PC ユーザーは追加アプリ不要。** 出力した .xlsx は Excel のほか、Excel for the web・Google スプレッドシート・
  LibreOffice でも開けること。
- **出力ファイルは後からローカルで編集できる。**
- 画面・メッセージ・コードのコメント・ドキュメントはすべて日本語。
- 構成は Vanilla JavaScript + ES6 モジュール。ビルド工程は設けない。
- 外部ライブラリは CDN から読み込み、バージョンを固定する。
  - ZIP の展開・作成: JSZip
  - Excel の作成: ExcelJS
- 主な利用環境は PC の Chrome / Edge。それ以外のブラウザでも、保存方法の代替（4.4）で使えること。

## 3. 入力仕様（KMZ）

主な入力は、箕面ハイキングアプリ（minoh-hiking）の写真出力で作られた KMZ。
1ファイルに写真が10〜20枚程度入っている。

### 3.1 KMZ の構成（minoh-hiking の出力形式）

```
xxx.kmz（ZIP。無圧縮で格納）
├─ doc.kml              … 写真1枚につき Placemark 1つ
└─ files/
   ├─ photo-001.jpg     … 写真本体（JPEG。PNG の場合もある）
   ├─ photo-002.jpg
   └─ ...
```

`doc.kml` の例:

```xml
<?xml version="1.0" encoding="UTF-8"?>
<kml xmlns="http://www.opengis.net/kml/2.2">
  <Document>
    <name>20261118_箕面</name>
    <Placemark>
      <name>箕面大滝</name>
      <TimeStamp><when>2026-11-18T01:32:10.000Z</when></TimeStamp>
      <description><![CDATA[<img src="files/photo-001.jpg" width="400" />]]></description>
      <Point><coordinates>135.472041,34.853667</coordinates></Point>
    </Placemark>
    ...
  </Document>
</kml>
```

| 属性 | 取り出し元 | 備考 |
|---|---|---|
| 名称 | Placemark 直下の `<name>` | Document の `<name>` と取り違えないこと。空のことがある |
| 撮影日時 | `<TimeStamp><when>` | UTC の ISO 8601。無いことがある |
| 位置 | `<Point><coordinates>` | `経度,緯度`（経度が先）。小数6桁 |
| 写真 | `<description>` 内の `<img src>` | KMZ 内の相対パス |
| タイトル | Document の `<name>` | 出力フォルダ名に使う |

### 3.2 読み込みの規則

- KML は `doc.kml` を優先し、無ければ ZIP 内で最初に見つかった `.kml` を使う。
- ZIP は無圧縮と Deflate の両方を読めること（他のアプリの KMZ にも備える）。
- 画像の参照は KML の置き場所からの相対パスとして解決する。大文字・小文字が違っても見つかるようにする。
- 位置が無い Placemark、画像が KMZ の外（`http://` など）にある Placemark は写真ではないとみなして飛ばす。
- 写真は、KMZ の中のバイト列を**そのまま**使う（再圧縮しない）。
- 名称が空の写真は、画面と出力で「写真001」のように番号で補う。
- KML が無い・壊れている・写真が1枚も無いときは、理由が分かるメッセージを表示する。

## 4. 出力仕様

### 4.1 出力フォルダの構成

```
20261118_箕面/                     … 出力フォルダ
├─ 20261118_箕面.xlsx              … 写真の一覧（KMZ と同じ名前）
├─ photos/
│  ├─ 001_20261118-1032_箕面大滝.jpg
│  ├─ 002_20261118-1045_展望台.jpg
│  └─ ...
└─ 20261118_箕面.kmz               … 読み込んだ KMZ そのもの（画面で選べる。既定は含める）
```

- **フォルダ名**: `YYYYMMDD_<KML の Document 名>`
  - 日付は写真の中で最も早い撮影日（日本時間）。撮影日時が1枚も無ければ出力した日。
  - Document 名が無ければ KMZ のファイル名（拡張子なし）。
  - Document 名が日付（`20261029-…`、`2026-10-29_…` など）で始まるときは、日付が2回入らないよう
    前に日付を付けず、Document 名をそのままフォルダ名にする（例: `20261029-ようらく台園地`）。
    minoh-hiking は出力時のファイル名（既定は `yyyymmdd-nn`）を Document 名にするため。
- **Excel のファイル名**: 読み込んだ KMZ と同じ名前で、拡張子を `.xlsx` にする
  （`20261029-ようらく台園地.kmz` → `20261029-ようらく台園地.xlsx`）。
- **写真のファイル名**: `番号3桁_YYYYMMDD-HHmm_名称.拡張子`
  - 日時は日本時間。撮影日時が無い写真は日時部分を省く（`001_箕面大滝.jpg`）。
  - 名称が空の写真は名称部分を省く。
  - 名称部分の空白（全角の空白・改行・タブを含む）は `_` に置き換える（`箕面 大滝` → `箕面_大滝`）。
    名称に元からある `-` は利用者が意図して付けたものとして残し、空白の置き換えと区別する
    （`Minoh - Falls` → `Minoh_-_Falls`）。
    続く空白や、空白の前後にある `_` は1つの `_` にまとめる。
    前後の空白は置き換えずに除く。
    写真は名前を付け直して保存するため、空白を含めなければ Excel の「写真ファイル」のハイパーリンクで
    空白の扱い（`%20` への置き換え）を考えなくてよい。Excel の「名称」列は元の名称のままにする。
  - フォルダ名・Excel・KMZ のファイル名は空白を残す（リンクは Excel ファイルからの相対パス
    `photos/…` なので、これらの名前に空白があってもリンクには影響しない）。
- ファイル名・フォルダ名から Windows で使えない文字（`\ / : * ? " < > |` と制御文字）を除き、
  末尾のピリオド・空白も除く。名称部分は長すぎないよう40文字程度で切る。
- 写真の並び順は撮影日時の昇順。撮影日時が無い写真は KML の順で末尾に置く。

### 4.2 Excel（KMZ と同じ名前の .xlsx）

シート名は「写真一覧」。1行目を見出しにし、写真1枚を1行にする。

| 列 | 見出し | 内容・書式 |
|---|---|---|
| A | No. | 1からの連番 |
| B | 写真 | サムネイル画像（下記） |
| C | 名称 | 文字列 |
| D | 撮影日時 | **日付型**（表示形式 `yyyy/mm/dd hh:mm`）。日本時間。無ければ空欄 |
| E | 緯度 | 数値（小数6桁） |
| F | 経度 | 数値（小数6桁） |
| G | 地理院地図 | ハイパーリンク `https://maps.gsi.go.jp/#17/緯度/経度/`（表示は「地図を開く」） |
| H | Google マップ | ハイパーリンク `https://www.google.com/maps?q=緯度,経度`（表示は「地図を開く」） |
| I | 写真ファイル | `photos/…jpg` への相対パスのハイパーリンク（表示はファイル名） |
| J | 備考 | 空欄（利用者が後から書き込む欄） |

- **サムネイル**
  - 写真を canvas で長辺 約400px に縮小した JPEG を埋め込む（Excel ファイルが重くならないように）。
  - 画像は「セルに合わせて移動する」配置にし、並べ替えで画像が行と一緒に動くようにする。
  - 行の高さは画像に合わせ、縦横比を保つ。
  - 縮小時は EXIF の向きを反映する（`createImageBitmap(blob, { imageOrientation: 'from-image' })`）。
- **日付の注意**: ExcelJS は JavaScript の `Date` を UTC として書き込む。
  日本時間で表示されるよう、9時間ずらした値を書き込むこと。
- 見出し行は太字・背景色付きにし、ウィンドウ枠を固定し、オートフィルターを付ける。
- 列幅は内容に合わせて調整する。
- 印刷設定: A4 縦、横1ページに収める、見出し行を各ページに繰り返す。
- 別シート「情報」に次の内容を書く。
  - 元の KMZ のファイル名、KML の Document 名、写真の枚数、出力日時、アプリ名
  - 注意書き: 「元の画質の写真は photos フォルダにあります。Excel に埋め込んだ画像は縮小版です。」

### 4.3 写真ファイル

- KMZ に入っていたバイト列をそのまま書き出す（縮小・再圧縮をしない）。
- 拡張子は元の画像形式に合わせる（jpg / png など）。

### 4.4 保存方法

1. **フォルダへ直接保存**（File System Access API の `showDirectoryPicker` が使えるブラウザ: Chrome / Edge）
   - 保存先（出力フォルダを作る親フォルダ）の中に出力フォルダを作って書き込む。
   - 同じ名前のフォルダが既にあるときは上書きせず、`(2)` のように番号を付けた名前で作る。
   - **保存先は「保存先を指定」で1回選べば覚えておく**（フォルダのハンドルを IndexedDB に保存する）。
     次からは保存先を選ぶ画面を出さずに、そのフォルダへ保存する。「保存先を指定」で選び直せ、「クリア」で忘れる。
   - 保存先が未指定のまま「フォルダに保存」を押したときは、保存先を選ぶ画面は出さず、
     「保存先を指定」でフォルダを指定するよう表示する。
   - 保存先に関するメッセージ（未指定・許可されなかった・見つからない・選ぶ画面を開けない）は、
     まだ何も書き込んでいない段階のため、エラー（赤）ではなく案内の表示（緑の枠）にする。
     エラー（赤）の表示は、保存の途中で失敗したとき（一部のファイルだけが保存されている可能性がある）、
     KMZ を読み込めないとき、必要なライブラリを読み込めないときに限る。
   - 書き込みの権限はブラウザが管理する。「フォルダに保存」を押したら `queryPermission` で確かめ、
     権限が無いときだけ `requestPermission` でブラウザの確認を出す。
     - 同じ訪問のうち（このサイトのタブを全部閉じるまで）は、一度許可されれば確認なしで書き込める。
     - 次の訪問の最初の保存では確認が出る。Chrome 122 以降はこの確認に「毎回許可」の選択肢があり、
       それを選ぶと以後は確認なしで書き込める（Chrome の永続的な権限の仕組み）。
     - 許可されなかったときは保存せず、もう一度押すか「保存先を指定」で別のフォルダを指定するよう表示する。
   - 保存先のフォルダが移動・削除されていたら、覚えた保存先を忘れ、「保存先を指定」で指定し直すよう表示する。
   - 読み込んだ KMZ と同じフォルダへの自動保存はできない（ブラウザは、ページに KMZ の置き場所を知らせないため）。
     KMZ を置くフォルダを保存先に選んでおけば、同じ使い方になる。
2. **ZIP でダウンロード**（すべてのブラウザ）
   - 出力フォルダと同じ構成を ZIP にまとめてダウンロードする。ZIP 名は出力フォルダ名と同じにする。
   - ZIP 内のファイル名は UTF-8 で格納する（日本語のファイル名が文字化けしないこと）。

直接保存が使えないブラウザでは、1 のボタンを出さずに 2 だけを出す。

**保存の確認**: 1・2 とも、ボタンを押してもすぐには保存せず、どこに何を保存するかを確認の画面で見せる
（どこに保存されるのか不安になる人がいるため。手間は1ステップ増えるが、安心して実行できることを優先する）。

- 保存先 → 作るフォルダ（または ZIP）→ 中身（Excel・photos フォルダと写真の枚数・KMZ）を、フォルダ・ファイルの木で見せる。
  - フォルダに保存: 保存先のフォルダ名の下に、新しく作る出力フォルダ。
  - ZIP: 「ダウンロード」フォルダの下に ZIP ファイル（ブラウザの設定でダウンロード先を変えている場合はその場所と書き添える）。
- 写真のファイル名は「写真のファイル名を見る(N 枚)」を開いたときだけ一覧で見せる。
- 同じ名前のものが既にあるときの扱い（フォルダは「名前 (2)」、ZIP はブラウザが番号を付ける）を書き添える。
- 「保存する」（ZIP は「ダウンロードする」）で保存し、「キャンセル」・Esc・背景を押したときは何もしない。
- フォルダに保存では、書き込みの権限の確認（4.4 の 1）は「保存する」を押した後に出す。
- 確認の画面に出した名前のとおりに保存する（画面を出す時点で保存の計画を決め、最後までそれを使う）。
  確認の画面を出している間は、別の KMZ を読み込まない。
- 保存先が未指定のときは、確認の画面は出さずに案内を表示する。

## 5. 画面仕様

1画面構成。PC の画面幅を主に想定するが、スマートフォンでも崩れないこと。

1. **ヘッダー**: アプリ名「Trail Album」と短い説明。
2. **KMZ の選択**: 「KMZ ファイルを選ぶ」ボタンと、ドラッグ＆ドロップの受け付け領域。
3. **プレビュー**（読み込み後に表示）
   - KMZ のファイル名・Document 名・写真の枚数・出力フォルダ名（予定）
   - 写真の一覧（サムネイル・No.・名称・撮影日時・緯度経度）。並び順は出力と同じ。
   - サムネイルを押すと元の写真を大きく表示する。
4. **出力**
   - 保存方法の使い分けの説明（チェックボックスの上）
     - フォルダに保存（Chrome・Edge）: 保存先のフォルダの中に、そのまま使える形で保存する。バックアップ向き。
       保存先は「保存先を指定」で1回選べば覚えること、ブラウザを開き直した後の最初の保存では許可の確認が出ることも書く。
       使えないブラウザでは、この項目を出さない。
     - ZIP でダウンロード（すべてのブラウザ）: 1つの ZIP にまとめる。人に送る・持ち運ぶとき向き。
       ダウンロード先は「ダウンロード」フォルダであること（ブラウザの設定で変えている場合はその場所）も書く。
       展開してから Excel を開くよう案内する（展開せずに開くと、写真へのリンクが働かない）。
   - 「元の KMZ も一緒に保存する」チェックボックス（既定は ON）
   - 保存先の表示（フォルダ名。未指定なら「（フォルダ未指定）」を薄く表示する）と、その右に
     「保存先を指定」ボタン・「クリア」ボタン（フォルダに保存できるブラウザのみ）。
     「クリア」は保存先が未指定のときは押せない。マウスを乗せると
     「保存先の指定を解除します（フォルダや写真は消えません）」と表示する。
   - 「フォルダに保存」ボタン（使えるブラウザのみ）と「ZIP でダウンロード」ボタン。
     押すと保存の確認の画面（4.4）を出し、「保存する」・「ダウンロードする」で保存する。
   - 処理中は進み具合（N / 全体の枚数）を表示し、ボタンを押せないようにする。
   - 完了したら保存先（フォルダ名・ZIP 名）を表示する。
5. **注意書き**（画面下部）
   - 「写真はこのパソコンの中だけで処理し、外部には送信しません。」
   - 「Excel は保存時に画像を圧縮することがあります。元の画質の写真は photos フォルダに保存されています。」

## 7. 開発・デプロイ

- ローカル確認: `public` フォルダで `python -m http.server 8000` を実行し、`http://localhost:8000` を開く。

  撮影日時が無い写真・名称が空の写真・日本語や記号を含む名称の写真も用意して確認する。
