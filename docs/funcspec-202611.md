# trail-album 機能仕様書

**最終更新日:** 2026年11月24日

---

## 1. 概要

### 1.1 アプリケーション名
trail-album（画面の表示は「Trail Album」）

### 1.2 目的
ハイキングで撮った写真の KMZ ファイルを読み込み、写真と属性（名称・撮影日時・位置）を一覧にした
**Excel ファイル（.xlsx）**と、**元の画質の写真ファイル**を1つのフォルダにまとめて保存する。

- 保存したフォルダは、KMZ のままでは中身を見にくい写真データのバックアップとして使う。
  Excel は「目次」、photos フォルダの写真は「元の画質のまま残す本体」という役割分担にする。
- 移動経路の GPX ファイルも読み込め、写真の撮影場所と一緒に地理院地図で確かめられる。
  GPX は内容の確認だけに使い、保存する内容には含めない。
- 主な入力は、箕面ハイキングアプリ（minoh-hiking）の写真の出力（KMZ）と移動経路の出力（GPX）。

### 1.3 基本方針
- 処理はすべてブラウザの中で行い、写真を外部へ送らない。
  ページの通信先は Content-Security-Policy（`connect-src 'self' blob: data:`）でこのサイトの中だけに限る。
- 保存した Excel は、Excel のほか Excel for the web・Google スプレッドシート・LibreOffice でも開ける形式にする。
- 写真は KMZ の中のバイト列をそのまま保存する（縮小・再圧縮をしない）。
- 画面・メッセージ・コードのコメント・ドキュメントはすべて日本語。

### 1.4 動作環境
- **プラットフォーム:** Web ブラウザ。主な利用環境は PC の Chrome / Edge
- **必須:** http(s) で配信すること（ES モジュールのため、`index.html` を直接開くと動かない）
- **必須のライブラリ:** JSZip と ExcelJS（CDN）。読み込めないときは、その旨を表示し、ファイルを選ぶボタンを押せなくする
- **任意の機能と必要な API**
  | 機能 | API・条件 | 使えないとき |
  | --- | --- | --- |
  | フォルダへ直接保存 | File System Access API（`showDirectoryPicker`）。https か localhost | 「フォルダに保存」のボタン・説明・保存先の欄を出さず、ZIP のダウンロードだけにする |
  | 保存先を覚える | IndexedDB | 覚えないだけで、保存は続ける |
  | 画像のコピー | Clipboard API（`navigator.clipboard.write` / `ClipboardItem`）。https か localhost | コピーのボタンを押せなくし、理由をツールチップに出す |
  | 地図 | Leaflet（CDN）と地理院タイル | 地図の代わりに「地図を表示できませんでした…」と表示する |
  | 列の幅を覚える | `localStorage` | 覚えないだけで、今の画面では幅を変えられる |
  | 写真の向きの補正 | `createImageBitmap`（`imageOrientation: 'from-image'`） | `<img>` で読み込む（`<img>` も EXIF の向きを反映する） |

### 1.8 処理の流れ
```
ファイルを選ぶ・置く
  → 種類の判定（app.js の fileKind）
  → KMZ: readKmz → excludeLoadedPhotos → 縮小版の作成 → buildAlbum
     GPX: readGpx → addSegments → buildTrack
  → プレビュー（写真の一覧・経路ごとの内訳）と地図（updateMap）
  → 保存: buildOutputPlan → 保存の確認 → buildWorkbookBlob → saveToFolder または buildZipBlob
```

## 2. 画面構成

画面は1枚で、縦に次の順で並ぶ。

| 領域 | 表示する条件 | 内容 |
| --- | --- | --- |
| ヘッダー | 常に | ロゴ、アプリ名「Trail Album」、説明「ハイキングで撮った写真の KMZ ファイルから、写真一覧の Excel と元の画質の写真をまとめて保存します。」 |
| 1 KMZ, GPX ファイルを選ぶ | 常に | ドラッグ＆ドロップの受け付け領域、「KMZ, GPX ファイルを選ぶ」ボタン、読み込みの結果（1ファイル1行） |
| 2 内容を確かめる | KMZ か GPX を読み込んでいるとき | 左に KMZ（写真）の列、境界線、右に GPX（移動経路）と地図の列 |
| 3 保存する | KMZ を読み込んでいるとき | 保存方法の説明、「元の KMZ も一緒に保存する」、保存先、保存のボタン、進み具合、結果 |
| 注意書き | 常に | 「写真はこのパソコンの中だけで処理し、外部には送信しません。」「Excel は保存時に画像を圧縮することがあります。元の画質の写真は photos フォルダに保存されています。」 |

重ねて出すもの（`<dialog>`）: 写真の拡大表示（4.2）、保存の確認（5.6）。

### 2.1 画面の幅
- 通常は、ヘッダー・各手順・注意書きの中身を最大 1040px にして中央に置く（左右の余白は 16px）。
- **地図を表示している間は、画面の幅いっぱいに広げる**（`body.is-wide`。左右の余白は 16px だけ残す）。
  ヘッダー・各手順・注意書きのすべてを広げる。地図を出せないとき（Leaflet を読み込めない）は広げない。
- 広がった分は GPX（地図）の列に回し、KMZ の列の幅は変えない（2.2）。

### 2.2 KMZ と GPX の列、境界線
| 項目 | 内容 |
| --- | --- |
| 列の幅 | KMZ の列の幅を決め、残りを GPX の列にする。既定の KMZ の幅は最大 463px（狭い画面では左右半分ずつ） |
| 最小の幅 | KMZ・GPX のどちらの列も 280px より狭くしない（画面の幅が変わったときも CSS の `clamp` で収める） |
| 設定値 | 既定の幅（463px）と最小の幅（280px）は `constants.js` に置き、`col-splitter.js` が CSS 変数（`--kmz-default-width`・`--col-min`）で `style.css` に渡す |
| 境界線 | 幅 40px の帯の真ん中に縦線を引き、帯のどこを掴んでも動かせる。つまみは画面の縦の真ん中に付いてくる（写真の一覧が長くても掴めるように）。マウスを乗せる・フォーカスする・動かしている間は、線とつまみを強調色にする |
| ドラッグ | マウス・タッチ・ペンで左右に動かす |
| キーボード | 境界線にフォーカスして ← → で 20px ずつ、Shift を押しながらだと 80px ずつ動かす |
| 元に戻す | 境界線をダブルクリックするか、Home キーで既定の幅に戻す |
| 記憶 | 決めた KMZ の幅（px）を `localStorage` の `trail-album.kmzColWidth` に保存し、次に開いたときも使う。元に戻すと消す |
| 支援技術 | `role="separator"`。`aria-valuenow` に KMZ の列が占める割合（%）を入れる |

### 2.3 狭い画面
| 画面の幅 | 変わるところ |
| --- | --- |
| 720px 以下 | KMZ と GPX を上下に並べ、境界線を出さない |
| 640px 以下 | カードの内側の余白を詰める |
| 480px 以下 | 写真の一覧の写真を 64px にし、表の左右の余白を詰める |

## 3. ファイルの読み込み

### 3.1 選び方
- 「KMZ, GPX ファイルを選ぶ」ボタン（`.kmz,.gpx`、複数選択可）か、ドラッグ＆ドロップで選ぶ。
- ドラッグ＆ドロップは**ページのどこに落としても受け付ける**（受け付け領域から外れて落とすと、
  ブラウザが KMZ をダウンロードしたり GPX をページの代わりに開いたりするため）。ファイルを持って
  ページに入ると、受け付け領域を強調する。
- KMZ・GPX はいくつでも一緒に選べる。**後から選んだファイルは、今の内容に追加する**（同じ写真・経路は重ねない: 3.6）。
- 同じファイルを続けて選んでも読み込む（選択欄の値を毎回空に戻す）。
- 読み込み中・保存中・保存の確認を出している間は、読み込まない。

### 3.2 種類の判定
1. 拡張子が `.kmz` なら KMZ、`.gpx` なら GPX。
2. 拡張子で分からないとき（拡張子が無い・`.xml` など）は、先頭 1024 バイトで見分ける。
   - `<gpx` を含めば GPX。
   - `PK`（ZIP の印）で始まり、`.kml` を含めば KMZ（.xlsx なども ZIP のため、ZIP というだけでは KMZ とみなさない）。
3. どちらでもないファイルは読み込まず、エラーの行を出す。

### 3.3 読み込みの順と結果の表示
- 選んだファイルを KMZ → GPX の順に、それぞれ選んだ順で1つずつ読み込む。
- 1つが読み込めなくても、残りのファイルは読み込む。読み込めなかったファイルは今の内容を変えない。
- 読み込み中は「「名前」を読み込み中…」「「名前」のサムネイルを作成中… i / N」を表示する。
- 終わったら、結果を**1ファイル1行**で表示する。表示は、追加があった側（KMZ・GPX）だけ最後に1回作り直す。

| 場面 | 種類 | メッセージ |
| --- | --- | --- |
| KMZ を追加した | 成功 | 「名前」を読み込み、写真を N 枚追加しました。（同じ写真があれば「(読み込み済みの写真と同じ M 枚は除きました)」） |
| KMZ の写真がすべて読み込み済み | 案内 | 「名前」の写真 M 枚は、すべて読み込み済みです(追加した写真はありません)。 |
| GPX を追加した | 成功 | 「名前」を読み込み、経路を N 本(記録地点 P 点)追加しました。／読み込み済みの経路 R 本を、記録地点が多いこのファイルの経路に置き換えました。（同じ経路があれば「(読み込み済みの経路と同じ S 本は除きました)」） |
| GPX の経路がすべて読み込み済み | 案内 | 「名前」の経路 S 本は、すべて読み込み済みです(追加した経路はありません)。 |
| 読み込めなかった | エラー | 「名前」: 理由（3.4・3.5 のメッセージ。それ以外は「読み込みに失敗しました(…)。」） |
| KMZ・GPX ではない | エラー | 「名前」…は KMZ, GPX ファイルではないため、読み込みませんでした。 |

### 3.4 KMZ の解析（`kmz-reader.js`）
KMZ は KML（地点の一覧）と画像を ZIP にまとめたもの。minoh-hiking の KMZ は次の構成。
```
xxx.kmz
├─ doc.kml           … 写真1枚につき Placemark 1つ
└─ files/
   └─ photo-001.jpg  … 写真本体（doc.kml の description から <img src> で参照する）
```
他のアプリの KMZ にも備え、「位置と、KMZ 内の画像への参照を持つ Placemark」を写真として読めるだけ読む。

| 項目 | 取り出し方 |
| --- | --- |
| ZIP | JSZip で展開する（無圧縮・Deflate とも読める） |
| KML | `doc.kml` を優先し、無ければ ZIP 内で最初に見つかった `.kml` |
| 位置 | `<Point><coordinates>経度,緯度[,標高]</coordinates>`。数値でない・範囲外（緯度 ±90・経度 ±180 を超える）の Placemark は飛ばす |
| 画像 | `<description>` 内の `<img src>`。`http:` などのスキーム付き・`//` で始まる参照（KMZ の外）は飛ばす。KML の置き場所からの相対パスとして `./` `../` を解決し、`?` `#` 以降を除き、URL エンコードを戻した名前でも探す。大文字・小文字が違っても見つける |
| 画像の形式 | 先頭のバイト列で JPEG・PNG・GIF・WebP を見分け、分からなければ拡張子（jpg / jpeg / png / gif / webp）で決める。どちらでも分からない画像は飛ばす |
| 名称 | Placemark **直下**の `<name>`（Document の `<name>` と取り違えないように）。空のことがある |
| 撮影日時 | `<TimeStamp><when>`（UTC の ISO 8601）。無い・読めないときは「撮影日時なし」 |
| タイトル | Document 直下の `<name>`。無ければ最初の Folder 直下の `<name>`。出力フォルダ名に使う |
| 写真のデータ | KMZ の中のバイト列をそのまま持つ（再圧縮しない） |
| KMZ のデータ | KMZ そのもののバイト列も持つ（読み込んだ後に元のファイルを移動・削除しても、KMZ を一緒に保存できるように） |

読み込めないときのメッセージ:
- KMZ(ZIP 形式)として読み込めませんでした。ファイルが壊れているか、KMZ ではない可能性があります。
- KMZ の中に KML ファイル(doc.kml)が見つかりません。写真の情報を読み取れませんでした。
- KMZ の中の KML ファイルが壊れていて、内容を読み取れませんでした。
- KMZ の中に写真が見つかりませんでした。位置と、KMZ 内の画像への参照を持つ地点(Placemark)がありません。

### 3.5 GPX の解析（`gpx-reader.js`）
GPX は移動経路を記録した XML。minoh-hiking の GPX は、記録1回ごとに `<trkseg>` を1本持つ。

| 項目 | 取り出し方 |
| --- | --- |
| 経路 | `<trkseg>` 1本を1本の経路とする。`<trkseg>` が無い GPX は、文書順の `<trkpt>` 全体を1本の経路にする |
| 記録地点 | `<trkpt lat lon>`。数値でない・範囲外の地点は除く。記録地点が1つも無い経路は除く |
| 記録時刻 | `<trkpt>` 直下の `<time>`（任意）。経路ごとに最初と最後の時刻を求める（1つも無ければ「記録時刻なし」） |
| 移動距離 | 隣り合う記録地点の間の大円距離（地球の半径 6,371,000m。minoh-hiking・Leaflet の `distanceTo` と同じ式）の合計 |

読み込めないときのメッセージ:
- GPX として読み込めませんでした。ファイルが壊れているか、GPX ではない可能性があります。（XML として読めない・ルート要素が `gpx` でない）
- GPX の中に移動経路の記録地点(trkpt)が見つかりませんでした。

### 3.6 同じ写真・経路の扱い（`merge.js`）
minoh-hiking は出力のたびにその時点の全部の写真・経路を書き出すため、同じ日に2回出力したファイルには同じ写真・経路が入る。
そのため、読み込むたびに重なりを除く。

| 対象 | 同じとみなす条件 | 扱い |
| --- | --- | --- |
| 写真 | 撮影日時・緯度・経度（小数6桁）・ファイルの大きさがすべて同じ（名称は minoh-hiking で後から変えられるため使わない） | 読み込み済みの写真と同じものは追加しない。同じ KMZ の中で重なる写真も1枚にする |
| 経路 | 最初の記録地点の記録時刻・緯度・経度（小数6桁）が同じ（記録の途中で出力した経路は、後で出力した経路の途中までと同じになるため） | 記録地点の多いほうを残す（多ければ置き換え、少なければ追加しない） |

### 3.7 並び順と記号
| 対象 | 並び順 | 記号 |
| --- | --- | --- |
| 写真（保存の順） | 撮影日時の昇順。撮影日時の無い写真は、読み込んだ順・KML の順で末尾 | 保存するファイル名・Excel の No. は 1 からの通し番号 |
| KMZ | いちばん早く撮った写真の順 | a, b, … z, aa, ab …（バッジの色は写真のマーカーの色） |
| GPX | いちばん早く記録した経路の順 | A, B, … Z, AA …（バッジの色は GPX ごとの地図の色） |
| 経路 | GPX ごとに記録の日時の順。記録時刻の無い経路は読み込んだ順で末尾 | A-1, A-2 … |

### 3.8 縮小版（サムネイル）
- 画面の一覧と Excel に使う縮小版を、読み込み時に写真ごとに作る（`thumbnail.js`）。
- 長辺 約400px（小さい写真は拡大しない）の JPEG（品質 0.85）。EXIF の向きを反映する。
  PNG の透明部分が黒くならないよう、白で塗ってから描く。
- ブラウザが表示できない形式で作れなかったときは「この形式は表示できません」とし、写真自体は保存できる。

### 3.9 クリア
- KMZ・GPX の列の見出しの右にある「クリア」で、読み込んだ KMZ（または GPX）をすべて画面から外す
  （ファイルは消えない）。読み込んでいないときは出さない。
- 結果に「読み込んだ KMZ をクリアしました。」（GPX も同様）を表示する。
- 地図は、外した分のマーカーと線を消すだけで、**中心と縮尺は変えない**（4.4.4）。
- 両方をクリアすると「内容を確かめる」を隠し、画面の幅も元に戻す。KMZ をクリアすると「保存する」も隠す。

## 4. 内容の確認（プレビュー）

### 4.1 KMZ（写真）の列
- **概要:** KMZ ファイルを記号 a, b … 付きで1つ1行に並べ、ファイル名の右にファイルごとの写真の枚数を出す
  （読み込み済みの写真と同じものを除いた、一覧に出している枚数）。KMZ が2つ以上のときは、その下に写真の枚数(合計)も出す
  （1つならファイルの行と同じ数になるため出さない）。
- **写真の一覧:** KMZ（a, b …）ごとに、撮影日時の順に並べる。1行に次の3列を置く。

| 列 | 内容 |
| --- | --- |
| No. / 名称 / 撮影日時 / 緯度, 経度 | `No.a-1` の形の番号（KMZ の記号と KMZ の中での順番）、名称、撮影日時（日本時間 `2026/11/18 10:32`）、緯度, 経度（小数6桁）を1行ずつ。名称が空なら「写真001」のように保存の通し番号で補い、薄く表示する。撮影日時が無ければ「(撮影日時なし)」を薄く表示する。名称にマウスを乗せると「保存するファイル名: …」を出す |
| 写真 | 縮小版を、右の4つのボタンを縦に並べた高さ（26px × 4 ＋ 間 4px × 3 ＝ 116px）の正方形に切り抜いて表示する（幅 480px 以下の画面では 64px）。押すと元の写真を大きく表示する |
| 操作 | 4.2 のボタンを縦に並べる |

### 4.2 写真の操作
| ボタン | 動作 | 押せないとき |
| --- | --- | --- |
| 拡大表示 | 元の写真を大きく表示する（写真の縮小版を押したときと同じ） | 縮小版を作れなかった写真 |
| 縮小版をコピー | 縮小版（長辺 約400px）をクリップボードにコピーする | コピーできないブラウザ、縮小版を作れなかった写真 |
| 画像をコピー | 元の大きさの画像をクリップボードにコピーする | 同上 |
| 画像を保存 | 元の写真を、保存するときと同じファイル名（5.2）でダウンロードする（KMZ の中のバイト列のまま） | — |

- コピーは PNG に変換して書き込む（ブラウザがクリップボードに書き込めるのは PNG のため。元の大きさのまま、EXIF の向きを反映する）。
  結果はボタンの文字で知らせる（「コピーしました」1.5秒、「コピー失敗」2.5秒）。
- 押せないボタンは、理由をツールチップに出す（「この形式は表示できません」「このブラウザでは画像をコピーできません(Chrome・Edge などで使えます)」）。
- **拡大表示:** 元の写真を画面の 96%（最大 1200px）・高さ 94% に収めて表示し、下に「No.a-1  名称  撮影日時」を出す。
  「×」・Esc・背景を押すと閉じる。

### 4.3 GPX（移動経路）の列
- **概要:** GPX ファイルを記号 A, B … 付きで1つ1行に並べ、ファイル名の右にファイルごとの記録地点数
  （経路が2本以上なら「1,234 点(3 経路)」）と移動距離（km、小数1位）を出す（読み込み済みの経路と同じものを除いた、
  内訳に出している経路の分）。GPX が2つ以上のときは、その下に記録地点数(合計)・移動距離(合計)も出す（1つなら出さない）。
- ファイルごとの数は、行どうしで列をそろえ、いちばん長いファイル名のすぐ右に置く（列が狭いときはファイル名を折り返す）。
- 「GPX は内容を確かめるためだけに読み込みます(保存する内容には含みません)。」と添える。
- **経路ごとの内訳:** GPX ごとに、ファイル名の行と、その経路（A-1, A-2 …）の行を並べる。

| 列 | 内容 |
| --- | --- |
| No. | A-1 など |
| 記録の日時 | 日本時間の範囲 `2026/11/18 10:32〜12:45`（日をまたぐときは終わりにも日付を付ける）。記録時刻が無ければ「(記録時刻なし)」 |
| 地点数 | 記録地点の数 |
| 移動距離 | km、小数1位 |

- 表が列に収まらないときは、表の中だけを横に動かせる。

### 4.4 地図
GPX の列の下に「地図(地理院地図)」を出す。KMZ の写真か GPX の経路があるときだけ表示する。

#### 4.4.1 表示
| 項目 | 内容 |
| --- | --- |
| 地図 | 地理院タイル（標準地図）。ズームレベルは 10〜18（縮小の下限 10・拡大の上限 18。`constants.js` の `MAP_MIN_ZOOM`・`MAP_MAX_ZOOM`）で、0.1 刻み（地点の範囲を地図いっぱいに収めるため。整数でないときは地図の画像を拡大・縮小して表示する）。「＋」「−」ボタンは 1 ずつ変える |
| 大きさ | GPX の列の幅いっぱいの**正方形**。ウインドウの幅を変えたり、境界線を動かしたりすると大きさが付いてくる |
| 描画 | 記録地点が数千になっても重くならないよう、canvas に描く円のマーカーにする |
| 右下の表示 | 上から、ズームレベルのボタン（「Z=16.3」。整数なら小数を付けない）、縮尺の目盛り（m・km）、地図の出典（Leaflet・地理院タイル） |
| ズームレベルのスライドバー | ズームレベルのボタンを押すと、その左に開く（もう一度押すか Esc で閉じる。ボタンは右端の同じ位置のまま）。縮小の下限〜拡大の上限を 0.1 刻みで変えられ、地図の中心を保ったまま拡大・縮小する。マウス・タッチでのドラッグのほか、フォーカスして矢印キーでも動かせる。動かしている間、ボタンには選んでいる値を出し、地図は拡大・縮小の動きを見せながらその値に追いつく（一気に変えると地図の画像をすべて読み直し、ちらつくため）。「＋」「−」ボタンやホイールでズームレベルが変わったときも、ボタンとスライドバーの値を合わせる。スライドバーの操作で地図がドラッグ・拡大されないようにする |

#### 4.4.2 マーカーと線
下から次の順に重ねて描く。

| 対象 | 見た目 | マウスを乗せたとき |
| --- | --- | --- |
| 経路の線 | 経路（A-1 …）ごとに記録の順に結ぶ。太さ 3、不透明度 0.6、GPX ごとの色。別の経路どうしはつながない | 「A-1」 |
| 記録地点 | 半径 3 の円、GPX ごとの色 | 「A-1 の 12 点目  2026/11/18 10:32」 |
| 写真の撮影場所 | 半径 7 の円、橙（`#e8590c`）、白い縁取り | 「a-1  名称」 |

GPX ごとの色は `#1c7ed6`（青）・`#7048e8`（紫）・`#0c8599`（青緑）・`#d6336c`（赤）・`#5c940d`（緑）・`#495057`（灰）の順で、7つ目からは繰り返す。
地図の下に凡例（「写真の撮影場所(N 枚)」「A の移動経路・記録地点」…）を出す。

#### 4.4.3 中心と縮尺
ファイルを読み込むたびに、読み込んだ地点すべて（写真の撮影場所・記録地点）の**東西南北の端**で地図を合わせる。
平均を使わないので、地点の数や偏り（休憩した場所に記録地点が固まる、同じ場所で写真を何枚も撮るなど）に左右されない。

- **中心:** 地点の範囲（最も北・南・西・東の地点で囲んだ範囲）の真ん中。地図の上（メルカトル図法の平面）で求め、上下・左右の余白をそろえる。
- **ズームレベル:** 範囲がすべて収まる、いちばん大きいズームレベル（0.1 刻み。17 まで）。
  最も北・南の地点が地図の上端・下端に、または最も西・東の地点が左端・右端に、縁から 24px 内側（マーカーの円が縁で切れないように）で届く。
  地図は正方形なので、範囲の縦横比により、どちらか一方が届く（もう一方は左右・上下の余白が同じになる）。
  0.1 刻みのため、端までの間が 24px より少し広くなることがある。地点が1つだけのときは 17。
  範囲がズームレベル 10（縮小の下限）でも収まらないときは 10 にし、範囲の真ん中を中心にする（端の地点は地図の外に出る）。

#### 4.4.4 合わせ直すとき・合わせ直さないとき
| 場面 | 地図の中心と縮尺 |
| --- | --- |
| KMZ・GPX を読み込んだ | 4.4.3 のとおり合わせる |
| KMZ・GPX をクリアした | 変えない（マーカーと線だけ置き直す） |
| 地図の大きさが変わった（ウインドウの幅・境界線） | 利用者が地図を動かしていなければ、4.4.3 のとおり合わせ直す。動かした後（ドラッグ・拡大・縮小）とクリアした後は、今の中心を保ったまま大きさだけ変える |

- 中心もズームレベルも変わらないときは地図を動かさない（動かすと地図の画像をすべて読み直し、ちらつくため）。
- 境界線を動かしている間は、地図の画像の読み込みを、動かし終えてからまとめて行う。

## 5. 保存

### 5.1 保存する内容
```
20261118_箕面/                       … 出力フォルダ（5.2）
├─ 20261118_箕面.xlsx                … 写真の一覧（5.3）
├─ photos/
│  ├─ 001_20261118-1032_箕面大滝.jpg  … 元の画質の写真（5.4）
│  └─ ...
└─ 20261118_箕面.kmz                 … 読み込んだ KMZ（「元の KMZ も一緒に保存する」が ON のとき。既定は ON）
```
- KMZ を複数読み込んでいるときは、すべての写真を1つのフォルダ・1つの Excel にまとめ、読み込んだ KMZ をすべて入れる。
- GPX は保存しない。

### 5.2 名前の決め方（`naming.js`）
| 対象 | 決め方 |
| --- | --- |
| 出力フォルダ | `YYYYMMDD_<タイトル>`。タイトルは KML の Document 名、無ければ KMZ のファイル名（拡張子なし）、それも無ければ「写真」。日付は全写真の中で最も早い撮影日（日本時間）、撮影日時が1枚も無ければ保存する日。**タイトルが日付で始まるとき**（`20261029-…`、`2026-10-29_…` など。年月日として正しい値のときだけ）は日付が2回入らないよう、タイトルだけにする |
| Excel | 読み込んだ KMZ と同じ名前で、拡張子を `.xlsx` にする |
| 写真 | `番号3桁_YYYYMMDD-HHmm_名称.拡張子`（日時は日本時間）。撮影日時が無ければ日時部分を、名称が空なら名称部分を省く。拡張子は画像の形式（jpg / png / gif / webp） |
| 元の KMZ | 読み込んだファイル名のまま。同じ名前が重なれば `名前 (2).kmz` のように番号を付ける（大文字・小文字は区別しない） |
| ZIP | `<出力フォルダ名>.zip` |

- **KMZ が複数のとき:** いちばん早く撮った写真の KMZ を代表とし、そのタイトル・ファイル名を出力フォルダ名と Excel のファイル名に使う。
- **使えない文字の除去（`sanitizeName`）:**
  - 改行・タブは空白1つにする。
  - Windows で使えない文字 `\ / : * ? " < > |` と制御文字を除く。
  - `#` と `%` も除く（Excel の「写真ファイル」のリンクで、`#` はファイル内の位置、`%` は文字コードの記号と解釈され、写真を開けなくなるため）。
  - 前後の空白を除き、長さで切ったうえで、末尾のピリオド・空白を除く（Windows は末尾のピリオド・空白を黙って削り、名前が食い違うため）。
  - 長さの上限は、名称部分・フォルダ名が40文字、元の KMZ のファイル名が120文字（絵文字などを途中で切らないよう、文字単位で数える）。
- **写真のファイル名の名称部分:** 空白（全角の空白・改行・タブを含む）を `_` に置き換える（`箕面 大滝` → `箕面_大滝`）。
  名称に元からある `-` は残す（`Minoh - Falls` → `Minoh_-_Falls`）。続く空白や、空白の前後にある `_` は1つの `_` にまとめる。
  空白を含めないので、Excel のリンクで空白の扱い（`%20`）を考えなくてよい。Excel の「名称」列と画面は元の名称のまま。
- 名前は**保存の確認の画面を出す時点で決め**、最後までそれを使う（確認した名前のとおりに保存する）。

### 5.3 Excel（`excel-writer.js`）
フォントは游ゴシック 11。作成者は「Trail Album」。

#### シート「写真一覧」
1行目を見出しにし、写真1枚を1行にする（保存の順: 3.7）。

| 列 | 見出し | 内容・書式 |
| --- | --- | --- |
| A | No. | 1 からの通し番号（中央） |
| B | 写真 | 縮小版の画像（下記）。縮小版が無ければ「(表示できません)」を薄く表示 |
| C | 名称 | 名称（空なら「写真001」）。折り返す |
| D | 撮影日時 | 日付型（`yyyy/mm/dd hh:mm`）。日本時間で表示されるよう、9時間ずらした値を書き込む（ExcelJS は Date を UTC として書くため）。無ければ空欄 |
| E | 緯度 | 数値（`0.000000`） |
| F | 経度 | 数値（`0.000000`） |
| G | 地理院地図 | 「地図を開く」→ `https://maps.gsi.go.jp/#17/緯度/経度/` |
| H | Google マップ | 「地図を開く」→ `https://www.google.com/maps?q=緯度,経度` |
| I | 写真ファイル | ファイル名 → `photos/ファイル名`（Excel ファイルからの相対パス）。折り返す |
| J | 備考 | 空欄（利用者が後から書き込む欄）。折り返す |

- **画像:** 縮小版を、縦横比を保ったまま長辺 150px 以内にして B列のセルの中央（上下の余白 8px）に置く。
  行の高さは画像に合わせる（縮小版が無い行は 30pt）。配置は「セルに合わせて移動やサイズ変更をする」にし、
  並べ替えで画像も行と一緒に動き、オートフィルターで絞り込んだ行の画像は隠れるようにする。
- **見出し:** 太字、背景色（薄緑 `#DDEBD9`）、中央、高さ 22pt。
- **罫線:** 全セルに細線（`#BFBFBF`）。リンクは青の下線。
- **列幅:** B列は 25、備考は 24。他の列は内容のいちばん長いものに合わせる（全角を2、半角を1と数えて +3。最小 6、最大 40。名称は最大 30、写真ファイルは最大 36）。
- **表示:** 1行目でウィンドウ枠を固定し、見出し行〜最終行にオートフィルターを付ける。
- **印刷:** A4 縦、横1ページに収める（縦は必要なだけ）、水平方向の中央、見出し行を各ページに繰り返す。

#### シート「情報」
| 項目 | 内容 |
| --- | --- |
| 元の KMZ ファイル | 読み込んだ KMZ のファイル名（複数なら1つ1行） |
| KML の Document 名 | Document 名（重なりと空を除き1つ1行。無ければ「(なし)」） |
| 写真の枚数 | 枚数 |
| 出力日時 | 保存した日時（日本時間、`yyyy/mm/dd hh:mm:ss`） |
| 作成アプリ | Trail Album |
| 注意 | 元の画質の写真は photos フォルダにあります。Excel に埋め込んだ画像は縮小版です。 |

印刷の設定は「写真一覧」と同じ。

### 5.4 写真ファイル
KMZ に入っていたバイト列をそのまま書き出す（縮小・再圧縮をしない）。

### 5.5 保存方法
画面には、2つの方法の使い分けを説明する（フォルダに保存できないブラウザでは、フォルダの説明を出さず、
「このブラウザはフォルダへの直接保存に対応していないため、ZIP でダウンロードします…」と添える）。

#### フォルダに保存（Chrome・Edge）
保存先（出力フォルダを作る親フォルダ）の中に出力フォルダを作って書き込む。

| 項目 | 内容 |
| --- | --- |
| 保存先の指定 | 「保存先を指定」でフォルダを選ぶ画面を出し、選んだフォルダを覚える（前の保存先があれば、そこから開く）。成功すれば「保存先を「名前」にしました。」。キャンセルしたときは何も出さない |
| 保存先の記憶 | フォルダのハンドルを IndexedDB（データベース `trail-album`、ストア `settings`、キー `lastSaveDir`）に保存する。次からは選ぶ画面を出さずに、そのフォルダへ保存する |
| 保存先の表示 | フォルダ名（ブラウザからは場所（パス）は分からない）。未指定なら「（フォルダ未指定）」を薄く表示する |
| クリア | 覚えた保存先を忘れる（フォルダや写真は消えない）。保存先が未指定のときは押せない |
| 未指定で保存 | 確認の画面を出さず「保存先が指定されていません。「保存先を指定」で、保存先のフォルダを指定してください。」と案内する |
| 書き込みの権限 | 確認の画面で「保存する」を押した直後に `queryPermission` で確かめ、権限が無いときだけ `requestPermission` でブラウザの確認を出す。同じ訪問のうちは一度許可されれば確認なしで書き込める。次の訪問の最初の保存では確認が出る（Chrome 122 以降は「毎回許可」を選べば以後は出ない） |
| 許可されなかった | 保存せず「保存先「名前」への書き込みが許可されませんでした。もう一度「フォルダに保存」を押して許可するか、「保存先を指定」で別のフォルダを指定してください。」 |
| 保存先が無い | 移動・削除されていたら覚えた保存先を忘れ、「保存先のフォルダ「名前」が見つかりません(移動・削除された可能性があります)。「保存先を指定」で、保存先のフォルダを指定し直してください。」 |
| 選ぶ画面を開けない | 覚えた保存先が消えたなどで開けないときは、覚えた保存先を忘れ、「保存先を選ぶ画面を開けませんでした。もう一度ボタンを押してください。」 |
| 同じ名前のフォルダ | 上書きせず `名前 (2)`、`名前 (3)` … と番号を付けて作る（同じ名前のファイルがあるときも同様。999 まで） |
| 完了 | 「「保存先」の中に「フォルダ名」フォルダを作り、保存しました。」（番号を付けたときは、その旨を添える） |
| 途中で失敗 | 「保存できませんでした(理由)。「フォルダ名」フォルダには一部のファイルだけが保存されています。」 |

読み込んだ KMZ と同じフォルダへの自動保存はできない（ブラウザは KMZ の置き場所をページに知らせないため）。
KMZ を置くフォルダを保存先に選んでおけば、同じ使い方になる。

#### ZIP でダウンロード（すべてのブラウザ）
| 項目 | 内容 |
| --- | --- |
| 構成 | 出力フォルダの中身を ZIP の直下に置く。Windows の「すべて展開」は ZIP 名のフォルダを作って展開するため、展開すると出力フォルダと同じ構成になる |
| 形式 | ファイル名は UTF-8 で格納する（日本語のファイル名が文字化けしない）。写真・xlsx・KMZ はもともと圧縮されているので、無圧縮で格納する |
| ダウンロード先 | ブラウザのダウンロード先（通常は「ダウンロード」フォルダ） |
| 完了 | 「「ZIP 名」をダウンロードしました。ZIP を展開してから「Excel 名」を開いてください(展開せずに開くと、Excel のリンクから写真を開けません)。」 |

### 5.6 保存の確認
「フォルダに保存」「ZIP でダウンロード」を押しても、すぐには保存せず、どこに何を保存するかを確認の画面で見せる。

| 項目 | フォルダに保存 | ZIP でダウンロード |
| --- | --- | --- |
| 題 | フォルダに保存します | ZIP でダウンロードします |
| 説明 | 保存先「名前」の中に、次のフォルダを作って保存します。 | 次の ZIP ファイルを「ダウンロード」フォルダにダウンロードします(ブラウザの設定でダウンロード先を変えている場合は、その場所になります)。 |
| 木の1段目 | 保存先のフォルダ名（保存先） | ダウンロード（ダウンロード先） |
| 木の2段目 | 出力フォルダ名（新しく作るフォルダ） | ZIP 名（ZIP ファイル） |
| 木の3段目 | Excel（写真の一覧(Excel)）、photos（写真 N 枚(元の画質のまま)）、KMZ（読み込んだ KMZ。含めるときだけ） | 同左 |
| 添え書き | 同じ名前のフォルダが既にあるときは、上書きせず「名前 (2)」のように番号を付けて作ります。 | 同じ名前のファイルが既にあるときは、ブラウザが番号を付けた名前にします。ZIP は展開してから Excel ファイルを開いてください。 |
| 実行のボタン | 保存する | ダウンロードする |

- 「写真のファイル名を見る(N 枚)」を開いたときだけ、写真のファイル名を一覧で見せる。
- 「キャンセル」・Esc・背景を押したときは何もしない。
- 確認の画面を出している間は、ファイルを読み込まない（確認した内容と違うものを保存しないように）。

### 5.7 進み具合と処理中の制御
- 進み具合は「Excel を作成中…」（件数の分からないバー）→「写真を保存中… n / N」（ZIP は「ZIP を作成中… n / N」）の順に出す。N は写真の枚数。
- 読み込み中・保存中は、ファイルを選ぶ・クリア・保存先の指定とクリア・保存のボタン・「元の KMZ も一緒に保存する」を押せなくし、
  受け付け領域を薄くし、カーソルを処理中の形にする。
- 保存の途中でページを閉じようとしたら、ブラウザの確認を出す。

### 5.8 メッセージの種類
| 種類 | 見た目 | 使う場面 |
| --- | --- | --- |
| 成功 | 緑の背景 | 読み込み・保存・保存先の指定・クリアが済んだ |
| 案内 | 緑の枠 | まだ何も書き込んでいない段階で、次に何をすればよいかを伝える（保存先が未指定・許可されなかった・見つからない、写真・経路がすべて読み込み済み） |
| エラー | 赤の背景 | 保存の途中で失敗した（一部のファイルだけが保存されている可能性がある）、ファイルを読み込めない、必要なライブラリを読み込めない |

## 8. 開発・公開
- **ローカル確認:** `public` フォルダで `python -m http.server 8000` を実行し、`http://localhost:8000` を開く
  （localhost なら、フォルダへの直接保存と画像のコピーも使える）。
- **Vercel:** `public` を出力先とする静的サイト（ビルドコマンドなし。`cleanUrls: true`、`trailingSlash: false`）。
- **GitHub Pages:** `main` に push するたびに GitHub Actions（`.github/workflows/pages.yml`）が `public` を公開する。
  リポジトリの Settings → Pages → Source は「GitHub Actions」にしておく。
